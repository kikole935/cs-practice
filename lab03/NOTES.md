• git log — это история и хронология. Команда показывает список (ленту) коммитов: кто, когда и с каким сообщением сделал изменения. Сам измененный код она по умолчанию не выводит — только метаданные.
• git show — это детали одного коммита. Команда берет один конкретный коммит (по его хешу или тегу) и выворачивает его наизнанку: показывает автора, дату, описание и сразу же весь измененный внутри него код.
• git diff — это сравнение состояний. Команда не привязана к истории, она просто берет две точки и показывает построчную разницу между ними. Например, что вы изменили в файле прямо сейчас по сравнению с тем, что было сохранено минуту назад.


git restore берет чистую версию файла из индекса (staging area), а git restore --source=... — из любого указанного коммита или ветки.
Что произойдет с вашими правками в рабочей директории:
• Они будут безвозвратно стерты. В обоих случаях файл на диске полностью перезапишется старой версией.
• Восстановить эти локальные изменения средствами Git будет невозможно.
Если нужно спасти текущие правки перед очисткой, хотите узнать, как использовать git stash или сделать временный коммит?


git reset --hard удаляет коммиты из истории и стирает текущие незакоммиченные файлы. git revert создает новый коммит, который зеркально отменяет изменения старого, не трогая прошлую историю.
В опубликованной истории безопасен только revert по одной причине:
• Если использовать reset, вам придется принудительно перезаписать историю на сервере через git push --force. У коллег локальная история разойдется с серверной. При следующем git pull удаленные коммиты вернутся обратно через автослияние, создав хаос и конфликты.
• Если использовать revert, история просто идет вперед. Вы делаете обычный безопасный git push. Коллеги без проблем скачивают коммит отмены через git pull, и плохой код исчезает у всех без конфликтов.
Правило: reset — для локального кода, revert — для сервера.
